# ADR 0001: Architecture for the AI resume builder

*Status: accepted by the founders on 2026-10-03. Chosen from three independently designed options scored by two judges, with platform facts verified live on 2026-10-03.*

## Context

The team cannot code: Claude Code writes and maintains all code. There is zero capital: everything must cost $0/month until revenue (accepted spend: a domain and $5-10 of prepaid LLM credit). The product requirements are in `research/Simple_SaaS_Pick_AI_Resume_Builder.md`.

## Decision: Hardened One-Worker Chokepoint Stack: Astro + React + Hono on Cloudflare Workers Free, D1 (split core/docs), Clerk sign-in, OpenAI gpt-5-nano/gpt-5-mini on prepaid credit, Dodo (USD) + Razorpay (INR/UPI)

This is Option C, which both judges picked, with the best ideas from A and B added and their factual errors corrected. One private GitHub repo, written entirely in TypeScript, deploys one Cloudflare Worker per environment (staging and prod). Workers Free allows commercial use; Vercel Hobby does not. Astro pre-builds the ~20 SEO pages, the pricing, policy and checker pages, and the /app shell as static files. Cloudflare serves these free, so they never count against the 100k requests/day quota. The editor is a React 19 single-page app. Everything heavy runs in the browser, which keeps the Worker inside the 10 ms CPU limit per request: the live preview and PDF export (@react-pdf/renderer, selectable text), DOCX export (docx), PDF/DOCX import text extraction (pdfjs-dist, mammoth), the diff, the rule checks and the match % math. The only server code is a small Hono /api. Every endpoint goes through one typed route() helper, which will not compile without an access level (public, user, paid, webhook or admin). User and paid handlers only receive a data repository that is already scoped to the caller's user ID. D1 has no public endpoint and no browser key, so there is no row-level-security rule that could be forgotten. D1 is split into two databases: 'core' (passes ledger, payments, quotas, settings, events, consents) and 'docs' (resumes and tailored versions). A restore of resume data then never rolls back payments, and the 500 MB free cap per database doubles. Clerk Hobby provides Google sign-in (basic scopes) plus an email link and a 6-digit email code, and sends those emails itself. That removes AI-written session code and the Resend 100/day magic-link bottleneck. AI calls go only through the Worker to OpenAI, with prepaid credit and auto-recharge off. gpt-5-nano handles import mapping, JD keyword extraction, free-user actions and the anonymous checker. gpt-5-mini handles paid rewrites, summaries and cover letters. An atomic quota reservation runs before every call and a token/cost log row is written after it. Plan limits, a daily USD budget and an AI kill switch live in a D1 settings table that a founder can edit without a deploy. Payments: Dodo (merchant of record) sells the USD one-time passes; Razorpay Orders plus UPI sells the INR passes. Both write to one append-only passes ledger, and access is computed from it at read time, so there is no cron and no auto-renew. Releases: GitHub Actions runs tests on Linux (which sidesteps the Windows issues), auto-deploys to staging, and promotes to prod on a human click. Before prod migrations it saves a D1 Time Travel bookmark, then runs a smoke test and rolls back automatically if it fails. Corrections applied from the judges: Dodo retries webhooks up to 8 times with the last attempt after 10 hours, not over about a day. Dodo and Razorpay both onboard unregistered Indian individuals with a PAN (plus Aadhaar/ID for Razorpay); this is confirmed, not unknown. The Clerk Pro price is unverified. Live policy pages before a Razorpay review are common practice, not a documented rule. Dodo's India-domestic rate also carries the international surcharge, which does not matter because INR goes to Razorpay.

## Security model

The design fails closed: the browser has no path to data except /api/*. (1) Secrets: the browser holds only public identifiers (Clerk publishable key, Turnstile site key, Razorpay key_id, Sentry DSN). Every secret is a Worker secret that a human pastes into a wrangler secret put prompt or a dashboard, never into chat or code: Clerk JWT key, OpenAI key, Dodo API and webhook secrets, Razorpay key secret and webhook secret, Turnstile secret, IP-hash salt. gitleaks scans the repo and CI scans the built browser bundle for secret patterns. (2) Data reach: D1 has no public endpoint or browser key and exists only as a Worker binding. Every endpoint goes through route(). User and paid routes verify the Clerk JWT, check Origin plus a JSON content-type (CSRF), validate input with zod, and check plan, consent and quota. Webhook routes verify the signature over the raw body, check the timestamp, dedupe events, and re-fetch from the provider. Admin routes require a verified email in ADMIN_EMAILS and return aggregates only. Handlers never touch env.DB. They get scoped(userId), where every query carries WHERE user_id = ?, and ids are unguessable UUIDv7. Lint rules and a CI grep enforce this. (3) Automatic tests cover every route and table: 401 matrix, IDOR matrix, public/webhook/admin route snapshot, deletion and export completeness across both D1 databases and the Clerk user. (4) Privacy: explicit AI consent before any resume text reaches the LLM. IPs are stored only as daily-salted hashes. No prompts or resume text in logs, Sentry or llm_calls. Deletion pseudonymises payment rows (amount, date, provider id kept for tax records) and erases everything else. The privacy policy discloses processors and retention: OpenAI keeps abuse logs up to 30 days, Clerk holds name and email, Cloudflare hosts the data, and backups keep data up to about 14 days plus the Time Travel window. Accept the OpenAI, Clerk and Cloudflare DPAs. What one mistake could still leak: (a) a query inside the tiny scoped repository written without the user_id filter would expose other users' resumes (name, phone, email, CGPA, work history), a DPDP/GDPR breach; it is mitigated by keeping that module small, the IDOR matrix, and a mandatory second Claude review pass on any diff touching src/server/data or core/route.ts; (b) a broken webhook verifier lets attackers grant themselves passes (revenue loss, not data exposure); (c) a logging slip copies resume text into Workers Logs (3 days) or Sentry (30 days); (d) a leaked OpenAI key is bounded by the prepaid balance. PDF and DOCX export happen in the browser, so the export paywall is soft by design. Server enforcement covers AI actions, imports, tailored-version counts and saved resumes.

## Risks and mitigations

- Free-plan cliffs cause outages, not bills: 10 ms CPU per request, 100k requests/day and the D1 daily write limit (when hit, all queries fail until 00:00 UTC). Mitigation: browser-side heavy work, IndexedDB drafts with debounced autosave, a write-count line in npm run costs and on /admin, and moving to Workers Paid ($5) at the first revenue instead of waiting for a cliff.
- An IDOR or missing-filter bug in code nobody on the team can review leaks resumes (personal data under DPDP and GDPR). Mitigation: the typed route() chokepoint, handlers that never see env.DB, generated 401 and IDOR matrices, a public/admin route snapshot test, and a second Claude review pass (/code-review, /security-review) on any diff touching src/server/data or core/route.ts before a prod release.
- AI cost abuse through many free accounts or the anonymous checker. Mitigation: Clerk signup bot protection, Turnstile, daily-salted IP caps, per-plan atomic quotas, a global daily USD budget, the ai_enabled kill switch in a D1 table, and prepaid OpenAI credit with auto-recharge off. The worst case is a day of exhausted free AI, not an unbounded bill.
- Payment onboarding and tax. Dodo and Razorpay KYC and website reviews take time. Put Terms, Privacy, Refund, Pricing and Contact pages live before applying (common practice). The status of a 2022 RBI pause on new Razorpay onboarding is unknown. Dodo's lack of FIRA/eBRC comes from a low-confidence third-party source. Razorpay is not a merchant of record, so GST on INR sales is the founder's job. Mitigation: start in test mode on day 1, apply early, confirm GST and income-tax treatment with an Indian CA before meaningful revenue, and keep the PaymentProvider adapter so Polar or Paddle can replace Dodo.
- Small models can invent facts or write weakly next to Rezi. Mitigation: the deterministic honesty flagger with per-flag confirmation, prompts that forbid new facts and use [placeholders], gpt-5-mini for paid-user writing, and model IDs kept in one config file so a better no-training model (for example Claude Haiku 4.5 at $1/$5) can be trialled for cover letters if conversion suffers.
- Clerk is a third-party processor and a lock-in point (US processing of name and email, branding on Hobby, unverified paid price). Mitigation: isolate it behind core/auth.ts, sign its DPA, disclose it, delete Clerk users on account deletion, and keep Better Auth on D1 as the documented exit path.
- Rollbacks: a code rollback does not undo migrations, and a Time Travel restore rolls back the whole database. Mitigation: additive-only migrations enforced in CI. The core/docs split means a resume-data restore never rewinds payments. A replay script re-applies provider payments after any core restore.
- Document fidelity: react-pdf pagination and fonts, DOCX simpler than the PDF, scanned image-only PDFs that cannot be imported without OCR, and complex Indic scripts untested (treat templates as English-only until tested). Mitigation: Playwright golden tests (screenshots, text extraction, ₹ glyph, selectability), plus a clear 'scanned PDFs not supported' message.
- Single-vendor concentration: hosting, database, DNS, domain and bot protection all sit on one Cloudflare account with no SLA on Free. Mitigation: code in GitHub, nightly encrypted off-platform dumps with automated test restores, a documented restore runbook, and 2FA recovery codes and the age private key in a shared password manager with 2 owners.
- Vendor and terms drift (Clerk limits, OpenAI model deprecations, Cloudflare free limits, Astro and adapter majors). Mitigation: pin dependency versions, keep model IDs and prices in single config files, and re-check every free-tier limit used here before launch and then quarterly. In week 1 verify the D1 Free daily row limits and the Clerk Hobby email-code and email-sending limits, which are unconfirmed in the fact sheet.

## Alternatives considered

### Option A: Supabase Postgres + Auth with row-level security (Mumbai region) behind Astro/React on Cloudflare Workers, Resend SMTP, Dodo + Razorpay

Same Astro + React + Workers front, but the browser reads and writes resumes directly in Supabase Postgres using the publishable key plus the user's JWT, protected by row-level security. About 12 Worker endpoints hold the secrets for AI, checkout, webhooks, coupons, deletion and admin. Quotas and grant_pass() are SECURITY DEFINER Postgres functions. Supabase Auth handles the magic link + 6-digit code and Google, with Resend as the required custom SMTP. CI runs an RLS-off gate and a two-user isolation test. Corrections if chosen: Dodo onboarding of individuals is confirmed, not unknown. A keep-alive Cron Trigger plus a pause alert is mandatory, because Free pauses after 1 week of inactivity. Dodo grants must dedupe on webhook-id AND payment id. Default to gpt-5-nano/gpt-5-mini instead of gpt-4.1-mini, which is about 4-8x the cost of nano. Keep the backup decryption key out of GitHub.

- **Better at:** Best long-term data platform: Postgres in the Mumbai region with SQL Claude knows well and no 10 GB per-database ceiling. A founder can edit limits and the kill switch in the Supabase Table Editor. Autosave and CRUD go straight to Supabase, so they never use the 100k/day Worker quota. Auth and users stay in your own database with no per-MRU auth vendor. The most complete feature fit, with an admin funnel page from day one.
- **Worse at:** Fails open, which is the worst property for a team that cannot review SQL. A table without RLS, a permissive policy, a view without security_invoker, or a SECURITY DEFINER function left with the default PUBLIC EXECUTE grant exposes resumes to anyone holding the public key, and the CI gate only catches the first case. Direct browser writes cannot be size-validated, so one user can bloat the 500 MB database. The free tier is fragile: no backups, a pause after 7 days, and up to 24 hours of data loss with nightly dumps. Resend's 100 emails/day can block magic links during a campus drive. 9 services to sign up for. Supabase Pro ($25/month) is effectively forced at the first revenue, versus $5 Workers Paid.

### Option B: Cloudflare-only stack with Astro + Hono + D1 (core/docs) + Better Auth on Workers Free, a Workers AI free lane plus an OpenAI paid lane, Resend email, Dodo + Razorpay

The same D1-behind-the-Worker architecture as the recommendation, but auth is self-hosted Better Auth (magic link + Google) storing users in your own D1, with Resend sending the magic-link emails. Free users and the anonymous checker use Cloudflare Workers AI (gpt-oss models), whose daily allowance cannot bill on Free. Paid users use OpenAI gpt-5-nano/mini on prepaid credit. As specified, deploys go through Cloudflare Workers Builds on branch push, with tests run on the laptop. Corrections if chosen: the Dodo fee on a $9 pass is about 10%, not 15%. Dodo charges $5 on payouts under $1,000. The D1 Free daily row limits and the Workers Rate Limiting binding's Free availability are unconfirmed. Better Auth's 'native D1 since 1.5' is unverified (the fact sheet confirms SQLite/D1 support through adapters). Adopt the recommendation's GitHub Actions gate instead of Workers Builds.

- **Better at:** Lowest possible cash cost: free-user and anonymous AI can run at a hard $0 on Workers AI. No third-party auth processor, so name and email stay in your own D1, with no MAU-based auth pricing ever and one fewer DPA. Everything except email and payments sits in one Cloudflare dashboard (8 services).
- **Worse at:** More AI-maintained moving parts: self-hosted auth library upgrades, a session cookie cache that delays revocation, and two LLM providers with different prompt and structured-output behaviour. gpt-oss-20b output quality and 'AI busy, try later' messages once the daily allowance runs out can hurt free-to-paid conversion against Rezi. Resend's 100/day cap is the magic-link bottleneck. As specified, its release engineering is the weakest: no CI gate, no automatic rollback, hand-written per-endpoint cross-tenant tests, a non-atomic quota upsert, drafts in localStorage, and only weekly off-platform backups.
